# Causoryn for Antigravity

> **Monorepo Development Fixture:** This directory (`integrations/antigravity/causoryn`) is a local monorepo development/testing fixture for verifying staged bundle compatibility. End users can install Causoryn via `npx causoryn@0.2.4 setup --client antigravity --yes` or from the repository root (`https://github.com/MrBekoX/Causoryn`).

> Evidence: TŞ v2.1 §17.1, §17.4, §22 · `docs/hosts/antigravity.md` · `packages/mcp-server` (29 published MCP tools)

**Causoryn** is a local, **LLM-free** codebase and change-intelligence engine exposed to Antigravity as a `stdio` MCP server (`causoryn`). Its structural analysis uses explicitly authorized workspace roots and fixed analysis rules. The optional `architecture-blueprint` skill in the distribution package guides the host model in providing `annotations` for an architecture export. The same snapshot and export inputs reproduce the same artifact. Regenerating the annotations in the host may produce different wording. [Antigravity host guide](../../../docs/en/hosts/antigravity.md)

## Requirements

- **Node.js >= 24** (`engines.node` in the monorepo root `package.json`).
- **Staged server bundle + vendored native SQLite runtime**: run from the repository root:

  ```bash
  npm run build:bundle --workspace packages/mcp-server
  ```

  This build produces `packages/mcp-server/dist/mcp-server.mjs`, `dist/node_modules/better-sqlite3/` (`package.json`, `lib/`, `prebuilds/`), and `dist/bundle-manifest.json`, and deterministically stages an identical copy into `integrations/antigravity/causoryn/scripts/`.
  - **Honest packaging note (ADR-010):** The staged artifact is **not** a single file. Because `better-sqlite3` loads native `.node` binaries that `esbuild` cannot inline, `scripts/mcp-server.mjs` and its sibling `scripts/node_modules/better-sqlite3/` directory travel together (git-ignored in source control, generated by the bundle step).

## Dual MCP Manifest Compatibility (`mcp_config.json` + `mcp.json`)

This plugin directory carries two synchronized MCP server definitions so both the built-in Antigravity customization loader and the TŞ §17.1 portable plugin specification resolve the same server cleanly:

1. **`mcp_config.json` (Primary — native Antigravity plugin loader):**
   The built-in Antigravity plugin loader discovers MCP servers from `<plugin_dir>/mcp_config.json` and spawns `node` with the plugin-relative entrypoint `"scripts/mcp-server.mjs"`.
2. **`mcp.json` (Portable manifest — TŞ v2.1 §17.1):**
   Uses `"${PLUGIN_ROOT}/scripts/mcp-server.mjs"` per the TŞ §17.1 portable plugin manifest contract (no fragile parent-directory `../../..` traversal into monorepo build folders, and no `--data-dir` CLI flag because `stdio.ts` reads configuration solely from `CAUSORYN_CONFIG`).
3. **`plugin.json` (Clean top-level manifest):**
   Contains only fields supported by the native Antigravity loader (`name`, `displayName`, `version`, `description`, `suggestedPrompts`). Unknown top-level keys such as `$schema` are intentionally omitted because the native loader silently discards them.
4. **Global server naming (`"causoryn"`):**
   MCP server names are global across a user's Antigravity configuration and all installed plugins. Both manifests register the server under `"causoryn"` rather than a generic `"engine"` key to prevent collisions.

## Workspace Authorization (`CAUSORYN_CONFIG` Default-Deny)

Both `mcp_config.json` and `mcp.json` ship with a strict **default-deny** configuration:

```json
{
  "allowRoots": []
}
```

- With `allowRoots: []`, workspace analysis tools fail closed with `WORKSPACE_NOT_AUTHORIZED` and index nothing.
- To authorize a project workspace for **read-only** analysis, set `CAUSORYN_CONFIG` to a JSON object with the absolute project path in `allowRoots`:

  ```bash
  CAUSORYN_CONFIG='{"allowRoots":["C:/projects/my-app"]}'
  ```

- Optional write targets also default to deny unless explicitly declared:
  - `output.allowedOutputDirs`: existing absolute directories where `causoryn_export_documentation` may atomically write exports (otherwise returns `EXPORT_NOT_ALLOWED`).
  - `wiki.dataDbPath`: an absolute SQLite file path **outside** every `allowRoots` workspace root for `causoryn_wiki_build` (otherwise returns `PATH_DENIED`).

## Security Guarantees

- **Read-only (`salt-okunur`) analysis:** Causoryn reads the authorized source tree. SQLite writes go to the data root outside the workspace, and export writes require `output.allowedOutputDirs` (ADR-008).
- **Analysis and rendering:** The MCP engine calls no model or embedding service. Setup and optional toolchain builds follow their own package retrieval rules. [Language analyzers](../../../docs/en/language-analyzers.md)
- **Clean stdio protocol:** `stdout` emits only JSON-RPC 2.0 MCP messages; diagnostic logs write exclusively to `stderr`.
