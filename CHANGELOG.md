### Changed

- **History tools are annotated as writing:** `causoryn_compare_architecture` and `causoryn_architecture_timeline` now declare `readOnlyHint: false`, like the other tools that write under the data root, and their descriptions no longer call them read-only. They store analyzed commits in `<data root>/history/` and never modify the workspace or git state. Hosts that run read-only tools without asking may now ask before these two.
- **History resource settings:** eight new environment variables bound the fresh commit analyses of the history tools; an invalid value is logged and ignored. `CAUSORYN_HISTORY_MAX_COMMIT_BYTES` (source text one commit analysis may read, default 32 MiB; it also sets the analysis worker's heap limit, 256 MiB plus 24 MiB per MiB of this budget, 1024 MiB by default, at most half of the machine's memory and 8192 MiB, never below 256 MiB), `CAUSORYN_HISTORY_MAX_REQUEST_BYTES` (source text all fresh analyses of one call may read, 64 MiB), `CAUSORYN_HISTORY_MAX_ANALYSIS_MS` (one analysis, `120000`), `CAUSORYN_HISTORY_MAX_REQUEST_MS` (all fresh analyses of one call, waiting included, `300000`), `CAUSORYN_HISTORY_MAX_CONCURRENT` (fresh analyses running at once in one server process, `1`), `CAUSORYN_HISTORY_BUSY_WAIT_MS` (how long a call waits for a free slot, `30000`; `0` does not wait), `CAUSORYN_HISTORY_CACHE_MAX_ENTRIES` (`256`) and `CAUSORYN_HISTORY_CACHE_MAX_BYTES` (1 GiB). A point stopped by one of these limits, or whose analysis worker runs out of memory or fails, is handled like a point over `CAUSORYN_HISTORY_MAX_ANALYSES`: it falls back to a committed snapshot when there is one, otherwise it stays unanalyzed with the reason `commit-byte-budget-exceeded`, `request-byte-budget-exceeded`, `analysis-deadline-exceeded`, `request-deadline-exceeded`, `analysis-busy`, `analysis-memory-exceeded` or `analysis-worker-failed` and a warning. Other calls keep being answered.
- **History analysis in a worker thread:** a fresh commit analysis now runs in the existing index worker (`dist/index-worker.mjs`, a new inventory-analysis mode; no new bundle file) with the capped heap above, so other tool calls keep being answered while it runs. An aborted analysis (deadline or call end) first asks the worker to stop its language sidecars, waits up to 1 s, then terminates the worker and kills any sidecar process it still reported (`%SystemRoot%\System32\taskkill.exe /pid <pid> /T /F` on Windows, `SIGKILL` elsewhere); a crashed or out-of-memory worker gets the same cleanup. The call returns within about 2 s, and the analysis slot stays taken until the worker thread has exited (at most 60 s). Up to 2 idle workers are kept for 30 s and reused.
- **Compare error codes for history limits:** a `causoryn_compare_architecture` side left unanalyzed by a limit now returns `LIMIT_EXCEEDED` (`analysis-budget-exceeded`, the byte budgets, the deadlines, `analysis-memory-exceeded`), the retryable `INDEX_NOT_READY` (`analysis-busy`, reported as is even while an index job runs) or the retryable `INTERNAL_ERROR` (`analysis-worker-failed`) instead of `INVALID_REVISION`; the message names the reason code. `commit-analysis-failed` and a missing snapshot stay `INVALID_REVISION`.
- **History cache retention:** after each store the cache keeps at most `CAUSORYN_HISTORY_CACHE_MAX_ENTRIES` entries and `CAUSORYN_HISTORY_CACHE_MAX_BYTES` in total (oldest first is evicted) and removes temporary files of writes that never finished. Cache entries now record the analyzed workspace (id and canonical root), so entries written by `0.3.2` are not reused and each commit is analyzed again once.
- **`causoryn setup` install record:** setup writes `~/.causoryn/installed-skills.json` (path and SHA-256 of every `SKILL.md` it wrote, and of every Causoryn skill it finds already up to date; a record it cannot read in full — below a link, not a regular file of at most 1 MiB, or in a format this version does not understand — is left as it is, and the action says `not recorded: …`) and replaces or removes only skills it can prove it installed (see Security). A skill you edited, or your own skill with a Causoryn skill name, is kept and reported as `skipped skill …` (setup) or `kept …` (uninstall).
- **Stricter repository acceptance:** a repository whose git directory holds a link that leaves the repository (for example `.git/hooks` pointing to another disk) is now refused with `PATH_DENIED`, and so are `.git` file, `commondir` and worktree pointers with an interior NUL, CR or LF or invalid UTF-8 (previously treated as absent). Move such a link inside the repository, or analyze a clean clone.
- **Plugin servers start from the plugin root:** the Codex, ZCode and Antigravity plugin manifests no longer start the server with the analyzed project as its working directory. The Codex plugin runs `node --input-type=module --eval <bootstrap> -- --expected-version … --allow-cwd …` without a `cwd`, with `env_vars: ["CODEX_HOME"]`: Codex starts it in the session directory and resolves `node` from `PATH` only, the bootstrap imports only `node:` built-ins and loads the launcher by its absolute real path in `<CODEX_HOME or ~/.codex>/plugins/cache/causoryn/causoryn/<version>/`, and it stops with exit code `2` on a missing or invalid version, a relative `CODEX_HOME`, a link below the cache or an install inside the workspace. `--allow-cwd` then binds the project after its safety check; no npm process runs and no project file is loaded. The ZCode plugin starts `node` in `${ZCODE_PLUGIN_ROOT}` and passes the project as the new launcher flag `--project-dir ${ZCODE_PROJECT_DIR}`, which the launcher validates and enters, so `--allow-cwd` still checks it. The root and Antigravity `mcp_config.json` / `mcp.json` keep `npx`, with `cwd: ${PLUGIN_ROOT}` and `--prefix ${PLUGIN_DATA}`, and bind the workspace through MCP `roots/list`. The Claude Code manifest is unchanged.
- **Export files:** graph and wiki exports are published through a temporary file the export creates itself, so a file named `<target>.tmp` next to the target is no longer deleted. The published file keeps the mode exports had before (`0666` narrowed by the process umask).

### Security

- **Workspace file reads bound to the opened file:** the inventory, contract discovery and the server's optional file reads share one bounded reader in `@causoryn/workspace`. The path is checked top-down from the canonical root (each component must be a real directory before anything below it is touched, the last one a regular file), the file is opened without following links and without blocking where the platform supports it, and the opened descriptor must be the checked file before and after the read. On Linux the descriptor's kernel path (`/proc/self/fd/<fd>`) must also be exactly the verified path before any byte is read; on macOS and Windows, where Node exposes no descriptor path, the guarantee rests on the path-based checks. The authorization decision is made on the bytes actually read; a file that does not pass is skipped (inventory) or refused (contract discovery).
- **Storage databases bound to their workspace root:** the graph and wiki databases record the canonical root of `allowRoots[0]` for their `workspaceId`. A database recorded for another root under the same `workspaceId` (an explicit `storage.dataDbPath` / `wiki.dataDbPath` reused for a second root) now stops startup with a `CausorynConfigError` and is left unchanged; use a separate database or a different `workspaceId` for each root. Storage schema v6 adds `workspaces.root_canonical`: a root recorded or upgraded by this version is compared as recorded, without following links, so a recorded root (or a parent of it) that later becomes a link is refused. A record written by `0.3.2` (unmarked) that names the same directory under another spelling (trailing separator, letter case, a link) is resolved once, rewritten to the canonical root by compare-and-set and marked; a legacy database that cannot be written, such as a read-only file, therefore stops startup. v1–v5 databases migrate on open; `0.3.2` does not use a v6 `graph.sqlite` (with `--auto-data-dir` it falls back to its own `graph.schema-5.sqlite`, an explicit `storage.dataDbPath` is refused with `storage/schema-too-new`). The default `--auto-data-dir` layout already uses one database per root.
- **Git metadata confined to the repository:** every `objects/info/alternates` entry (nested and relative entries included, resolved where git resolves them) and a linked `objects` directory must stay inside the analyzed root, its git directory or its common directory. Git metadata paths (the `.git` file pointer, `commondir`, alternates, config include paths, `core.worktree`, the worktree back-pointer) are resolved both the way git on POSIX resolves them (`..` after links) and the way Git for Windows does (lexically), and a path whose two readings differ is refused. On POSIX a backslash is a file-name character (also when it ends a directory name), relative includes of a linked config resolve against the including file's own directory, `lstat`/`readlink`/`realpath` errors other than a missing entry are refusals, and a `..` after a path component that does not exist is refused. Each check has a total budget of 10,000 file system operations (`MAX_LAYOUT_FS_OPERATIONS`; an identically spelled path is resolved once), past which the repository is refused, and git then runs with `-C` at the canonical root that was validated. A refused repository returns `PATH_DENIED` from the Git-based tools before git starts; the reason is in the server log and names no location outside the root. Linked worktrees and submodules keep working. Git metadata files are opened first (non-blocking, `O_NOFOLLOW | O_NOCTTY` where defined) and judged on the opened descriptor: a directory reads as absent, anything that is not a regular file is refused without being read, and the path must still name the opened file afterwards. Metadata is parsed byte for byte the way git parses it: `.git` file, `commondir` and worktree pointers with an interior NUL, CR or LF or invalid UTF-8 are refused; `objects/info/alternates` is split on LF only, quoted entries are unquoted to bytes (octal escapes included), text after a closing quote is checked as a further entry, and entries with CR, LF or NUL are refused; include paths and `core.worktree` must be valid UTF-8, and a `%(prefix)/` include is checked after interpolation (an absolute rest goes through the network/device check, a relative rest is refused). Links directly in the git and common directory and anywhere below `refs/`, `info/`, `reftable/`, `worktrees/`, `logs/` and every object directory must stay inside the analyzed root, its git directory or its common directory; a directory is listed once per depth, and every open and directory listing counts toward the operation budget. Working-tree blob reads open with `O_NONBLOCK | O_NOCTTY` where defined.
- **Export publication:** the export's temporary file has a random name, is created exclusively (`wx`) by the export itself, and is the only file the export ever removes. The target directory must be the authorized, link-free directory from authorization to the rename, and before any content is written and again before the rename the entry at the temp path must be the file the export's descriptor refers to; otherwise the publication is refused (`PATH_DENIED`) and nothing is published.
- **History analysis and cache trust:** fresh commit analyses run within the byte, time, memory and concurrency limits above (checked between tree entries and blob reads, at every progress message of the worker and by a timer that terminates it, and passed to every git process as its timeout). The cache directory is used only as a real directory directly inside the data directory and, on POSIX, owned by the server's user and not writable by group or others; its identity is checked again right before each temporary-file create, rename and unlink. Each entry must pass the same owner and mode checks on its path and on the opened file and must name the analyzed workspace. Anything else is ignored with a log line, never served.
- **`causoryn setup` and `doctor`:**
  - A `SKILL.md` is replaced or removed only when its bytes match the install record, or it is exactly the shipped skill or a skill version Causoryn shipped up to `0.3.2`. A file that changes between planning and execution (for example during the confirmation prompt) stops the run before any change: `<file> changed while setup was running, so it was left as it is. Run setup again.`
  - Host config diagnostics (Codex TOML values, JSON syntax errors) name the file, the line/column and the key, never the value or the surrounding text, in text and `--json` output. The `startup_timeout_sec` note reports only the parsed number.
  - The ZCode fallback `~/.agents/mcp.json` is read without following links (no linked parent below the home directory, a regular file of at most 1 MiB); only its own server names are copied, and `__proto__`, `constructor` and `prototype` are skipped and reported.
  - An existing `~/.causoryn` must be a real directory and, on POSIX, owned by the current user and not writable by group or others before the runtime is staged, the install record is written, or host configs are pointed into it (for example when setup runs from `~/.causoryn/runtime` with `--no-skill`); this is checked while planning, `--dry-run` included. Setup otherwise stops with `Refusing to use <dir>: it is owned by another user …` or `… it is writable by other users (mode …)`; `--uninstall` then ignores the install record instead of failing.
  - Setup rejects a `nodeExecutable` (programmatic setup option) that is not an absolute path.
- **Release checksum verification:** the `publish` job requires the downloaded `SHA256SUMS.txt` to be byte-for-byte identical to the two-record list (tarball, then SBOM) it rebuilds from the `build-and-pack` job outputs, and runs `sha256sum --strict -c` only on that locally generated list. The `build-and-pack` digests step applies the same byte-for-byte check before it exports the digests.
- **Contract discovery work budget:** OpenAPI and AsyncAPI specs are indexed once per document (one key index per map, a line table for line evidence), and each `$ref` shape is resolved and expanded once. A total projection work budget per spec document (`MAX_PROJECTION_WORK_UNITS`, 1,000,000 deterministic work units, four times `MAX_SPEC_NODES`; emitted text counts one unit per full 64 characters) bounds the projection; a spec over it fails with the existing `contracts/limit-exceeded` (`LIMIT_EXCEEDED`; the message carries counts only). YAML duplicate-key checking is linear in contract parsing and in the discovery sniff, and JSON Schema `required` matching is linear. Output for ordinary specs is unchanged.
- **Architecture guard YAML:** `.causoryn/architecture.rules.yaml` and `.causoryn/architecture.baseline.yaml` are parsed with the same linear duplicate-key check (same tree and errors as before; `@causoryn/graph` now depends on `@causoryn/contracts` for it).
- **Host manifest launch:** no shipped plugin manifest lets the analyzed project's directory, npm configuration, `node_modules` or `node_modules/.bin` decide what starts the server: servers start in the plugin root, `npx` manifests pin npm's prefix to the plugin's data directory, the project reaches the ZCode launcher only as a validated `--project-dir`, and the Codex plugin, whose server runs in the project directory, loads the launcher only by its absolute path in Codex's plugin cache. The Codex manifest also sets `NoDefaultCurrentDirectoryInExePath` in its `env`, so `cmd.exe` (inside a `.cmd` / `.bat` shim on the way to Node) and the server's child processes never search the project, and the bootstrap stops when the `node` binary lies inside the workspace or when a `PATH` entry before Node's directory is empty or not an absolute local path. Residual for the Codex plugin: an empty or relative `PATH` entry before Node's directory can still select a project `node`, which then runs instead of the bootstrap; the manifest cannot name an absolute Node binary because Codex expands no variables and has no per-platform command (`causoryn setup` registers the absolute Node binary and is not affected); a different marketplace name, a remote executor or a changed Codex cache layout makes the bootstrap stop instead. `server.json` adds `--ignore-scripts`; the MCP Registry format has no working-directory field, so a registry client that runs `npx` in the project directory still uses that project's npm context (documented residual), and the Claude Code manifest, which has no `cwd` field, leaves the spawn directory to the host. `tests/host-manifest-launch-safety.test.ts` checks every manifest and launches the staged package as the ZCode, Codex and Antigravity manifests do.
- **Dependencies:** the lockfile updates `hono` 4.13.16 → 4.13.18 and `@hono/node-server` 2.1.6 → 2.1.11. Both are transitive dependencies of the MCP SDK and are not part of any shipped bundle; `tests/bundle-transport-absence.test.ts` checks that every shipped bundle contains no HTTP transport and imports no Node HTTP module.

## [0.3.2] - 2026-11-25

### Release Decision

**`0.3.2` is a Pre-1.0 patch release — explicitly NOT `1.0.0`.** It closes two data exposures found in a security review before the project's public announcement; the MCP tool surface, envelope schema and configuration stay compatible with `0.3.1`, so no migration is needed. Root `package.json`, every workspace package, `packages/causoryn/package.json`, `SERVER_VERSION`, `INDEXING_VERSION`, `server.json`, and the four host marketplace/plugin manifests are kept in sync at `0.3.2`. The open gates under `[Unreleased]` keep `1.0.0` closed.

### Security

- **No absolute workspace path in exports:** the Workspace node no longer carries `attributes.rootPath`. Before this, `causoryn_export_documentation` with `format: "snapshot"` (the file meant to be committed as `.causoryn/architecture-snapshot.json`) and `format: "json"` with `view: "full"` contained the machine's absolute workspace path, which includes the OS user name and the local folder layout. Snapshots exported by earlier versions still contain it: export them again before committing them. Comparing such an older snapshot with a newer point reports the Workspace node as changed once. A new test exports every format and checks that no artifact contains the workspace path.
- **No source text in contract parse errors:** a spec that fails to parse (`CONTRACT_PARSE_FAILED`) is now reported with the parser's error code and the line/column only. Before this, the message quoted the offending source lines, so a malformed config file such as `appsettings.json` could show a credential to the agent and in the server log.

### Fixed

- **README release status:** it no longer says the current release changed the default tool surface; that change shipped in `0.3.0`.

## [0.3.1] - 2026-11-25

### Release Decision

**`0.3.1` is a Pre-1.0 patch release — explicitly NOT `1.0.0`.** It fixes `causoryn_find_symbols` ranking and lets the history tools analyze commits without committed architecture snapshots; the MCP tool surface, envelope schema and configuration stay compatible with `0.3.0`, so no migration is needed. Root `package.json`, every workspace package, `packages/causoryn/package.json`, `SERVER_VERSION`, `INDEXING_VERSION`, `server.json`, and the four host marketplace/plugin manifests are kept in sync at `0.3.1`. The open gates under `[Unreleased]` keep `1.0.0` closed.

### Added

- **Commit analysis for the history tools:** `causoryn_compare_architecture` and `causoryn_architecture_timeline` analyze a commit that the local index does not cover from its git objects. The tree is listed and the blobs are read with the hardened read-only git calls (no checkout, nothing written into the workspace), and a scratch in-memory index analyzes the files the workspace rules would index; symlinks, submodules, ignored and secret paths are never read. Commit points have the same symbol-level detail as index points. Source files come from the commit; project and build inputs outside the source inventory (C# `.csproj` / `Directory.Build.props`, installed `node_modules` / NuGet packages) and the workspace rules come from the working tree and the current config. A committed `.causoryn/architecture-snapshot.json` is now only the last fallback.
- **History cache:** analyzed commits are cached under `<data root>/history/`, only when the data root is outside every workspace root (exclusive temporary file + rename, owner-only mode). The cache key covers the Causoryn and indexing versions, the analyzer fingerprint schema and the workspace rules; corrupt or oversized entries are removed and the commit is analyzed again. A commit analyzed without a language worker is analyzed again once the index has run that worker.
- **`CAUSORYN_HISTORY_MAX_ANALYSES`:** how many commits one call may analyze fresh (defaults: compare `2`, timeline `4`). Cached commits do not count; points over the budget stay unanalyzed with `analysis-budget-exceeded`, and the next call continues from the cache. Internal seams: `IndexServiceOptions.inventorySource` (an in-memory inventory for the async index run) and `ContextOverrides.historyMaxFreshAnalyses`.

### Fixed

- **History tools in repositories without committed snapshots:** compare `HEAD~1` → `HEAD` failed with `INVALID_REVISION` (`manifest-not-found`) and every timeline point stayed unanalyzed unless `.causoryn/architecture-snapshot.json` was committed at each ref. Those commits are now analyzed from their git objects (see Added). The engine's own analysis also takes precedence over a committed snapshot file, which is used only as the last fallback with its trust warning.
- **`causoryn_find_symbols` ranking:** project symbols now rank ahead of `UnknownExternal` placeholders (calls into code outside the workspace) below the exact-match tier. Previously a loose query such as `Service` returned prefix-matching placeholders like `service.get` first and the project's own `IBasicCacheService` only at position 27 on a real repository. Exact matches keep their place; `kind: "UnknownExternal"` queries are unchanged. The `0.3.0` notes said placeholders were dropped whenever project symbols match; only placeholders that share a project symbol's name are dropped, and that sentence is corrected below.

## [0.3.0] - 2026-11-24

### Release Decision

**`0.3.0` is a Pre-1.0 release — explicitly NOT `1.0.0`.** The minor version is bumped because the default MCP tool surface changed in a breaking way (29 tools → an 11-tool `core` profile). Root `package.json`, every workspace package, `packages/causoryn/package.json`, `SERVER_VERSION`, `INDEXING_VERSION`, `server.json`, and the four host marketplace/plugin manifests are kept in sync at `0.3.0`. The open gates under `[Unreleased]` keep `1.0.0` closed.

### Breaking Changes

- **Default tool surface reduced from 29 to 11 tools.** Without options, `tools/list` now returns the `core` profile: `causoryn_status`, `causoryn_map_system`, `causoryn_find_symbols`, `causoryn_get_symbol_context`, `causoryn_trace`, `causoryn_get_agent_context`, `causoryn_preflight_change`, `causoryn_verify_change`, `causoryn_contracts`, `causoryn_get_evidence`, `causoryn_export_documentation`. Calls to legacy names that are not in the active profile fail with an MCP "tool not found" error.
- **Living Wiki and architecture-history tools are opt-in.** The 7 `causoryn_wiki_*` tools need `--tool-profile wiki`; `causoryn_compare_architecture` and `causoryn_architecture_timeline` need `--tool-profile history`.
- **`outputSchema` is omitted from `tools/list` by default** to keep the listing small. Responses still carry `structuredContent`, and the server validates every envelope against its schema in both modes.
- **One shared index per workspace.** All hosts now use `<data-dir>/workspaces/<slug>-<hash12>/graph.sqlite` instead of one `graph-<client>.sqlite` file per host; `--client` only labels the host. The SQLite schema moves to `user_version = 5`. When `graph.sqlite` does not exist yet, the newest valid per-host `graph-<client>.sqlite` written by `0.2.x` is copied into it once; the legacy files are left in place and `causoryn doctor` lists them.
- **ZCode shares the index with the other hosts.** The base data directory is now `--data-dir` > `~/.causoryn` for every host; `ZCODE_PLUGIN_DATA` is only a fallback when `~/.causoryn` cannot be created or written. ZCode users whose index lived under `ZCODE_PLUGIN_DATA` re-index once.
- **Index job status `reused`.** Job records (`causoryn_status` `data.index.job`, legacy `causoryn_index_status`) report `status` `queued`, `running`, `done`, `reused`, `failed` plus `outcome` (`published`, `unchanged`, `reused_peer`, `peer_busy`, `failed`) and `published`. A run that publishes nothing is now `reused` (or `failed` with outcome `peer_busy`), never `done`; clients that polled for `done` must also accept `reused`.
- **Analyzer fingerprint `fp3`.** Real TypeScript declaration spans, ESM/CommonJS module-format detection, and English evidence text changed analyzer output, so snapshots and `file_facts` written by earlier releases are not reused: the first `0.3.0` start re-indexes each workspace once.
- **Go 1.26 minimum.** The Go worker and `causoryn doctor` require Go 1.26, the oldest Go release line that still gets security fixes (`native/go-worker/go.mod` was `go 1.22`). With an older Go, `doctor` reports `DEGRADED` and Go files fall back to L0/L1 analysis.
- **Stricter workspace boundaries from the security hardening.** A root that is only a subdirectory of a git repository no longer reads that parent repository (Git-based tools report the ref as not found); `causoryn setup` stops when a host configuration directory below the home directory is a symbolic link or junction (`CLAUDE_CONFIG_DIR` / `CODEX_HOME` can point at the real directory); architecture policy YAML rejects aliases; NuGet package folders outside the trusted NuGet roots and the workspace are ignored with a warning; `--allow-cwd` refuses projects inside `~/.config` or `~/Library` (use `--root`).

### Migration

- **Keep the legacy tool names:** start the server with `--tool-profile full` (or set `CAUSORYN_TOOL_PROFILE=full`). This registers all 29 legacy names plus `causoryn_status`, `causoryn_trace`, and `causoryn_contracts` (32 tools). Superseded legacy tools are marked `(Deprecated: use <replacement>)` and add a deprecation warning to their responses.
- **Move to the consolidated names:** `causoryn_get_capabilities`, `causoryn_workspace_summary`, `causoryn_index_status`, `causoryn_refresh_index` → `causoryn_status` (`action: "inspect"` or `action: "refresh"`); `causoryn_generate_onboarding` → `causoryn_map_system`; `causoryn_trace_execution`, `causoryn_trace_business_flow` → `causoryn_trace`; `causoryn_analyze_impact`, `causoryn_derive_test_plan` → `causoryn_preflight_change`; `causoryn_check_architecture` → `causoryn_verify_change`; `causoryn_check_contracts`, `causoryn_detect_contract_drift` → `causoryn_contracts`.

### Added

- **Tool profiles (`--tool-profile core|full|wiki|history`, `CAUSORYN_TOOL_PROFILE`, `CAUSORYN_CONFIG.toolProfile`):** the `core` listing stays within a 15,000-character `tools/list` budget (`tests/mcp-tool-surface-budget.test.ts`); profiles can be combined with commas. The bare bundle entry (`dist/mcp-server.mjs`) and `causoryn mcp` resolve the tool profile, `CAUSORYN_MCP_OUTPUT_SCHEMA_PROFILE` and `CAUSORYN_INDEX_WAIT_MS` through the same resolver.
- **Non-blocking `worker_threads` indexing and MCP progress notifications:** full and incremental indexing run in a dedicated worker (`packages/indexing/src/index-worker.ts`, bundled as `dist/index-worker.mjs`) over SQLite WAL (`PRAGMA busy_timeout = 5000`), with an in-process async fallback. Clients that send `_meta.progressToken` receive `notifications/progress`. Tools other than `causoryn_status` wait up to `CAUSORYN_INDEX_WAIT_MS` (default 15,000 ms; `0` disables waiting) for the first index and otherwise return `status: "partial"` with `{ status: "indexing", jobId, progress, retryAfterMs }`. While a re-index runs, responses serve the latest published snapshot with a `stale=true` warning.
- **Per-file incremental indexing with early cutoff (`file_facts`):** schema v4 adds the `file_facts` table (`content_hash`, `public_interface_hash`, `imported_paths_json`, serialized per-file graph facts). Together with TypeScript `oldProgram` reuse, body/comment-only edits re-analyze only the changed file, and snapshot IDs stay byte-identical to a full rebuild.
- **Shared workspace database with single-writer leases:** one `graph.sqlite` per workspace for all hosts, coordinated by the `build_leases` table (`lease_id`, `owner_pid`, `host_label`, `hostname`, `owner_instance`, `heartbeat_at`, `expires_at`; default TTL 120 s, heartbeat 10 s). On the same host PID liveness decides and the TTL is secondary; a heartbeat older than the hard staleness ceiling (10 min, `CAUSORYN_LEASE_STALE_CEILING_MS`) counts as dead, which also covers PID reuse; on another host only the TTL counts (it is long because the build write phase can hold the SQLite write lock for tens of seconds). The heartbeat is renewed from the main thread every 10 s and at every phase boundary. `recoverOrphanBuilds` marks `building` rows left by a crashed process as recovered orphans so the next build can publish.
- **Waiting for a live peer build:** async runs claim the build lease before analysis; when a live peer holds it they wait (progress phase `waiting_for_peer`, up to `CAUSORYN_PEER_WAIT_TIMEOUT_MS`, default 15 min) and then reuse the peer's snapshot without re-analysis when the inputs match (`outcome: "reused_peer"`).
- **Schema forward guard and legacy migration:** a `graph.sqlite` stamped by a newer schema is never opened for writing (`storage/schema-too-new`); the CLI uses `graph.schema-<N>.sqlite` instead. Legacy `graph-<client>.sqlite` files are migrated once (read-only `quick_check`, online backup, no-clobber publish).
- **`causoryn setup --tool-profile <list>`** writes `--tool-profile <list>` into every generated entry (`core`, `full`, `wiki`, `history`, or a comma list); `--all-detected` is an explicit alias of the default host selection.
- **`causoryn doctor` toolchain minimums and legacy files:** probes the .NET 10 runtime (`dotnet --list-runtimes`), Python 3.10 and Go 1.26, reports per-toolchain `status` (`ok`, `warn`, `absent`) and `minimumVersion`, and lists legacy `graph-<client>.sqlite` files (read-only; never deletes them).
- **Warm boot, streaming snapshot hashing, and retention GC:** `computeStreamingSnapshotId` hashes the same canonical bytes as before without building one large string (IDs are unchanged); `getLatestSnapshotMeta` avoids hydrating the full graph on startup; `MAX_PUBLISHED_CACHE_ENTRIES = 1` lowers warm memory; `pruneOldSnapshots` keeps the newest 2 published snapshots and removes orphan rows, including orphan `symbol_fts` entries.
- **Semantic fidelity:** TypeScript monorepo workspace package resolution (`package.json` `name`/`exports`/`types`/`main`/`workspaces`, confined to `rootDir`); class-hierarchy edges (`INHERITS`, `IMPLEMENTS`) for TypeScript (`TypeChecker`) and C# Roslyn (`INamedTypeSymbol.BaseType`/`Interfaces`), used by impact analysis and `causoryn_preflight_change`; read-only C# NuGet reference discovery from `obj/project.assets.json` (bounded, symlink/UNC-guarded); per-language `coverage.byLanguage` in envelopes so one language cannot hide degradation in another.
- **Code localization in `causoryn_get_agent_context`:** identifier and path tokenization (`camelCase`, `PascalCase`, `snake_case`, `kebab-case`) with SQLite FTS5 BM25 plus structural-degree ranking; production sources rank above test files and `UnknownExternal` placeholders unless the query asks about tests; matched external concepts propagate one hop back to their production callers.
- **Trusted history sources:** `causoryn_compare_architecture` and `causoryn_architecture_timeline` (`history` profile) prefer the published local index when it provably matches a commit's content (indexed file hashes on disk, git blob IDs equal to the commit tree, every other path excluded by the workspace rules) and use it instead of the working-tree snapshot file for `working-tree`. Points that still come from a committed `.causoryn/architecture-snapshot.json`, which a pull request can change, carry the explicit trust warning `snapshot-loaded-from-committed-git-blob`, and refs served from the index are listed in `warnings`.
- **Real-repository evaluation harness (`scripts/bench/real-repo-eval.mjs`):** evaluates the packed tarball on the Causoryn repository and on small TypeScript/Go/Rust judge fixtures (tool count, `tools/list` size, event-loop stall, warm handshake, unresolved-edge ratio, localization rank).

### Changed

- **Edge resolution honesty:** the Go adapter keys packages by directory path plus `go.mod` module path (fixing multi-file packages and preventing false cross-directory `verified` matches between separate `package main` directories); the Rust adapter labels 2-segment suffix matches (`Type::method`, `mod::fn`) as `heuristic` with the `unverified-module-prefix-suffix-match` ambiguity instead of `verified`, and calls with several candidates are `unresolved` (no edge to any candidate) with every candidate listed in `ambiguity`.
- **TypeScript analysis:** symbol nodes carry their real declaration spans; each file's ESM/CommonJS format follows the nearest `package.json` `type` field and the `.mts`/`.cts` extensions. C#, Python, Go and Rust symbol nodes still carry a 1:1 file-anchor span (a documented limitation).
- **English runtime text:** all runtime text, including native worker warnings and rationales (for example `reference pack loaded: ...` from the Roslyn worker), is plain English; the stderr ready marker is `causoryn mcp server ready (causoryn@<version>)`; the Living Wiki template version is `1.1.0` (English templates), so wikis built with `1.0.0` are rebuilt on the next build.
- **Warm start refresh:** when a published snapshot exists, it is served immediately and one background incremental refresh picks up files changed while the server was not running.
- **`causoryn_verify_change`:** `checks` defaults to `["architecture", "graph-diff", "test-plan"]` (`contracts` runs when requested or when contract pairs exist); working trees are projected asynchronously for all languages; `.causoryn/architecture.rules.yaml` and `architecture.baseline.yaml` are read from the trusted Git `baseRef` (`HEAD` by default), with an explicit `trustWarning` when the untrusted working tree is used instead; host-supplied test runs are recorded only as `state: "host_asserted"` (`engineVerified: false`).
- **Other tool behaviour:** `derive_test_plan` resolves saved `preflightId` manifests from `PreflightManifestStore`; impact analysis no longer walks noisy `CONTAINS` edges in reverse BFS; `causoryn_trace` clamps oversized `maxDepth`/`maxPaths` with a warning; `find_symbols` drops `UnknownExternal` placeholders that share their name with a real project symbol; annotation validation reports up to 25 errors in one pass; `errors.ts` carries English `userAction` guidance.
- **`causoryn setup`:** no longer treats a bare `~/.gemini` as Antigravity (requires `~/.gemini/antigravity` or `~/.gemini/config/mcp_config.json`); writes nothing and exits `1` with guidance on `stderr` when no host is detected and neither `--client` nor `--all` is given; repeated runs are no-ops; re-running keeps every key of the existing Causoryn entry that setup does not own (`env`, `disabled`, `autoApprove`, `alwaysAllow`, `timeout`, unknown keys keep their value and position) together with the `--tool-profile` and `--output-schema` arguments, and a Codex `startup_timeout_sec` of 30 or more is kept (a lower or unusable value is raised to 30 and reported); the first original `*.causoryn.backup` is kept and later edits get timestamped backups; temporary files are removed in `try/finally`; host configs use the absolute Node binary (`process.execPath`) instead of a bare `node`.
- **`causoryn doctor`:** accepts absolute Node executable paths and reports `NOT CONFIGURED` (no configured host) or `DEGRADED` (host warnings, or a toolchain that is installed but below its minimum or unusable) instead of a false `HEALTHY`.

- **Typecheck coverage:** `npm run typecheck` now also covers `integrations/*/causoryn/test` and `apps/*/src`.

The nightly off-peak run (`schedule`, 03:17 UTC) and manual dispatch add an Apple Silicon `macos-26` leg.

The wiki tree walk tolerates cyclic parent links, and the onboarding learning order is computed in O((V+E) log V) with unchanged output.

### Fixed

- **TypeScript call resolution:** calls through anonymous call signatures (lib, external, and workspace functions such as `String`, `expect`, injected handlers) no longer produce false `unresolved` edges; genuinely unresolved callees stay `unresolved`, and multi-line chained call text is collapsed to at most 120 characters.
- **Status without graph hydration:** workspace summaries are served from snapshot metadata instead of loading the full graph.
- **C# implicit global usings:** C# analysis now models SDK implicit global usings (`<ImplicitUsings>enable</ImplicitUsings>` plus `<Using Include/Remove>` items), so SDK-style projects no longer get false `CS0246`/`CS0103` diagnostics for BCL types such as `Console` or `Thread`. Each `.csproj` is compiled as its own Roslyn compilation (with its `ProjectReference` closure and the nearest `Directory.Build.props`), which also removes false `CS7022` warnings caused by merging several projects into one compilation.
- **Windows short-path workspace roots:** a workspace root given by its 8.3 short name (for example `C:\Users\RUNNER~1\...`) no longer turns every `node_modules` import into a false `TS2307`; modules resolved under the root’s real path are accepted.
- **`safe.directory` forwarding follows git:** when the user’s environment sets `GIT_CONFIG_NOSYSTEM`, the system-level `safe.directory` entries are not forwarded, matching what git itself reads.
- **Declaration spans for every language:** C#, Python, Go and Rust symbol nodes now carry their real declaration lines (an optional `span` field in the worker protocol, validated by the adapters) instead of a `1:1` file anchor, so agent context and symbol tools point at the declaration in every language. The Go worker's limit message now reads `file count limit exceeded`, matching the other workers.
- **C# external call names:** `UnknownExternal` names for library calls no longer repeat the namespace (previously for example `System.System.Console.WriteLine`).
- **False `TS1470` in ESM projects:** the confined compiler host now exposes each workspace `package.json` `type` field, so files in `"type": "module"` packages are no longer analyzed as CommonJS.
- **Honest job states:** an index run that publishes nothing is no longer reported as `done`; a host whose peer published first reports `reused` with outcome `reused_peer`.
- **Worker responses after process exit:** a language worker that answers and then exits (stdin is closed after the request) no longer has its response replaced by "worker exited (exit=0)" and an L0/L1 fallback when Node reports the exit before the last stdout chunk; the early-exit outcome waits for the stdio streams to close (or 1 s after exit).
- **Publish under concurrency:** the publish transaction takes the SQLite write lock up front (`BEGIN IMMEDIATE`), and lease heartbeats are renewed from the main thread while the indexing worker is busy, so a live build is not mistaken for an orphan.

### Security

- **Toolchain isolation when analyzing untrusted repositories:**
  - Cargo builds run with `CARGO_BUILD_RUSTC_WRAPPER=""` outside the analyzed repository, and the compiled worker is pinned by `causoryn-rust-worker.sha256.json` (source fingerprint + `O_NOFOLLOW` binary SHA-256 check before spawn).
  - Read-only Git calls set `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=<devNull>`, `GIT_ATTR_NOSYSTEM=1`, `GIT_NO_LAZY_FETCH=1` (honoured by git 2.45 and later), `GIT_LFS_SKIP_SMUDGE=1`, `GIT_OPTIONAL_LOCKS=0`, and pre-subcommand `-c` overrides (`core.fsmonitor=false`, `core.hooksPath`, `core.sshCommand=false`, `diff.external=false`, `protocol.allow=never`, `protocol.ext.allow=never`, `safe.bareRepository=explicit`); relative revisions such as `HEAD~N` and `HEAD^` are resolved with `rev-parse --verify --end-of-options`.
  - The Go worker forces `GOTOOLCHAIN=local`, `GOWORK=off`, `GOPROXY=off` and drops `GOENV` from its environment allowlist; the Python worker starts with `-I -B -X utf8` from its own directory; the Roslyn worker pins its working directory and sets `DOTNET_STARTUP_HOOKS=""`; `doctor` probes run in `os.tmpdir()`; `sidecar-ipc` enforces `shell: false`, `windowsHide: true`, and a non-empty `cwd`.
  - Every tool the MCP server starts (`git`, `dotnet`, `python`, `go`, `cargo`) is resolved to an absolute path from `PATH` entries outside the analyzed workspace and started from a trusted working directory; on Windows `taskkill` is taken from `System32`.
  - The Rust worker is built from a staged copy of its crate in Causoryn's build cache (`CAUSORYN_RUST_TARGET_DIR`; a cache inside the workspace is refused); an explicitly configured worker directory is never built in place.
  - Git children additionally get an empty `GIT_ALLOW_PROTOCOL` and per-protocol `protocol.<name>.allow=never` pins; partial-clone (promisor) repositories are refused on git older than 2.45; the user's system and global `safe.directory` entries are forwarded with `-c`.
- **Path safety:** a shared lexical check rejects UNC and Win32 device paths (`\\host\share`, `//host/share`, `\\?\`, `\\.\`) before any filesystem call; project-root safety also rejects `$HOME` ancestors (`C:\Users`, `/home`, `/Users`) and `/tmp`, `/var`, `/bin`, `/sbin`, `/lib`, `/dev`.
- **Interactive HTML portal:** `script-src 'unsafe-inline'` is replaced by a deterministic `script-src 'sha256-<hash>'` Content Security Policy.
- **Git reads confined to the analyzed repository:**
  - A root without its own `.git` no longer falls back to a parent repository (`GIT_CEILING_DIRECTORIES` is the parent of the canonical root). A `.git` file may only point inside the root, or to a linked worktree or submodule git directory that points back to it. A `.git` entry that is a symbolic link is not followed.
  - Network (UNC) and device paths in the gitdir pointer, `commondir`, alternates, config include paths and `core.worktree` are refused before git starts.
  - Read commands are limited to the exact `cat-file` / `ls-tree` / `rev-parse` forms Causoryn uses (no textconv or filter forms), and every repository-bound call runs with `--no-pager` and an empty `credential.helper`.
  - Source-revision resolution checks the gitdir pointer before touching its target and never reads `HEAD`, refs or `packed-refs` through a symbolic link. Its size-limit notes no longer include exact file sizes.
- **Workspace and output path policies:**
  - On Windows they reject, before any stat or realpath, alternate data streams (`:` after the drive), segments ending in a dot or space, reserved device names, the `\??\` prefix, and links whose target is a UNC or device path.
  - Ignore rules are re-checked against the native long-name path, so 8.3 short names and letter-case aliases no longer bypass deny globs.
  - The part of a root below a declared `allowRoot` is re-inspected on every call.
  - The file inventory no longer hands link entries to the policy, and it stops with `LIMIT_EXCEEDED` beyond 256 nested directories.
  - `storage.dataDbPath` and `wiki.dataDbPath` reject UNC, device and aliased declarations before filesystem access.
  - `--allow-cwd` and MCP roots/list also reject `~/.config`, `~/.docker`, `~/.azure`, `~/.gcloud`, `~/.npm`, `~/.cargo`, `~/Library`, `%APPDATA%` and `%LOCALAPPDATA%`, including their 8.3 spellings.
- **Policy and baseline files:**
  - They are read only when they are regular files inside the workspace. Symlinked or junctioned path segments, FIFOs and devices are refused on every platform, and the opened descriptor's identity is checked against the verified path.
  - The YAML no longer accepts aliases, and parse errors report the error code and line/column without echoing file content.
  - Files are bounded: at most 500 rules, 1000 suppressions, plus capped field lengths and error-message size.
- **Language adapters:**
  - **TypeScript:** the confined compiler host resolves links component by component before any filesystem access. It never follows a link to a UNC/device path or out of the workspace and the TypeScript lib directory. `node_modules` declaration reads are bounded (16 MiB per file, 512 MiB per run, regular files only), and the host never writes files, exposes the process environment or lists the disk.
  - **C#:** NuGet `packageFolders` from `obj/project.assets.json` are used only inside trusted NuGet package roots (`NUGET_PACKAGES`, the user-level NuGet.Config folders, `~/.nuget/packages`) or the workspace. Workspace project reads refuse intermediate links. The Roslyn worker loads each reference on its own, skips empty or non-regular reference DLLs, validates `DOTNET_ROOT`, and runs with `DOTNET_EnableDiagnostics=0` and an empty `DOTNET_ADDITIONAL_DEPS`.
  - **Python:** recursion limits are isolated per file, so the rest of the batch is still analyzed, and rendered expression text is capped at 200 characters.
- **Native toolchains:**
  - On Windows, process trees are stopped with `taskkill /T` before the direct kill, and child environments set `NoDefaultCurrentDirectoryInExePath=1`.
  - `causoryn doctor` resolves toolchains to absolute paths and probes them from their installation directory.
  - The Go worker also runs with `GOENV=off`, `GOFLAGS=-mod=readonly` and `CGO_ENABLED=0`.
  - Rust worker builds always use `--locked`, and target directories must be absolute local paths. The build cache is private to the current user, and cached binaries and their pins must be single-link files owned by that user. The pin is computed from the freshly built bytes, and the binary's identity is re-checked right before it starts. Builds are refused when another user's cargo/rustup configuration sits above the build directory.
- **Rendering and storage:**
  - Markdown and Mermaid exports (architecture brief, full-view Mermaid, offline wiki Markdown, annotation overlay) escape repository and annotation text per output context. Fences, headings, HTML, links, images, bare autolinks and Mermaid directives cannot be introduced through symbol names, paths or notes.
  - The standalone viewer's CSP allows its embedded script and stylesheet only by SHA-256 hash (no `'unsafe-inline'`).
  - Offline wiki export files are written through unique exclusive-create temp files.
  - SQLite databases are created owner-only (0o600, including `-wal`/`-shm`), and every connection (including the read-only wiki search connection) runs with `PRAGMA trusted_schema = OFF`. A database with a negative `user_version` is refused.
  - Wiki full-text search treats NUL bytes as whitespace and reports FTS5 errors as invalid-argument errors.
- **Release and supply chain:**
  - The publish job checks the downloaded tarball and SBOM against SHA-256 digests that `build-and-pack` exports before any packaged code runs, and requires `SHA256SUMS.txt` to list both files. Existing GitHub Release assets are never overwritten.
  - The security workflow adds `cargo-audit` (0.23.0, `--deny warnings`) for the Rust worker lockfile and `govulncheck` (v1.10.0) for the Go worker.
  - The SBOM lists the SQLite library compiled into the bundled better-sqlite3 prebuilds, and esbuild moved to `devDependencies`.
  - Plugin manifests anchor their entry scripts at the host's plugin root (`${PLUGIN_ROOT}` for Antigravity), and `npx` manifests pass `--ignore-scripts`.
  - `causoryn mcp` and the plugin launcher accept an inherited `CAUSORYN_ASSET_ROOT` only when it points at a causoryn package of the same version with `native/`.
- **Secret scanning and setup:**
  - `secret-scan` and the public export gate share one scanner. It covers every tracked and untracked-not-ignored file, detects binaries by content, adds detectors for more credential families plus generic user-profile and local-path detectors, supports an optional untracked private-term list (`.git/info/causoryn-private-terms` or `CAUSORYN_PRIVATE_TERMS`), and fails closed on read errors.
  - The export gate reads the committed tree directly, so `.gitattributes export-ignore` cannot hide files from it.
  - `causoryn setup` refuses to write, back up or stage through linked directories below the home directory, and never overwrites an existing backup. `--uninstall` removes only the skills and runtime files Causoryn created, without following links.
- **MCP tool trust and limits:**
  - `causoryn_verify_change` no longer reports `no_findings` when architecture rules or the baseline were read from the working tree instead of a trusted git ref: a result that would otherwise be clean becomes `review_required` (rationale rule `untrusted-rules`). The report records `rulesProvenance` and `trustWarning`, and host-supplied test evidence ids stay in the test-run section.
  - Every string and array in the tool input schemas has a finite maximum. `causoryn_architecture_timeline` accepts at most 100 refs, and onboarding limits are clamped to documented ceilings with an `onboarding/limit-clamped` warning.
  - A roots/list_changed rebind no longer moves an in-flight tool call to the new workspace or closes its database; the previous context is closed after its calls finish.
  - A git repository layout that would read outside the analyzed root is reported as `PATH_DENIED` with a fixed message (the reason goes to the server log). `LIMIT_EXCEEDED` messages for policy, baseline and git blob reads name the limit but no longer the file's exact size.
