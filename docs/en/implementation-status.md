# Implementation Status

> **Language:** [Türkçe](../implementation-status.md) | **English** · [Documentation Hub](README.md)

> **Status:** reflects Causoryn 0.3.2 (default `core` tool profile with 11 tools; `wiki`, `history` and `full` add the rest — see [MCP Tool Contracts](tool-contracts.md)). `1.0.0` is not declared; the open gates are listed in [section 3](#3-remaining-100-release-gates) and in the [Engineering Backlog](BACKLOG.md).

**Honesty policy:** nothing that is broken, unimplemented, or unexecuted is marked `Done`. Partial work is labelled `Partial`, checks that were never executed are labelled `NOT RUN`, and every known limitation is stated next to the capability it limits.

## How to Read This Page

| Marker | Meaning |
|---|---|
| **[C]** | Re-checked against the 0.3.0 source tree (file read / `grep`) when this page was revised. The named tests cover the behavior; the marker does not claim a fresh test run. |
| **[D]** | Verified directly on disk on the date of the record (file read, `grep`, `ls`, `git log/diff`, or a live command whose output is summarized). |
| **[R]** | Task report verified by the release lead at the time (failing-first → passing evidence collected during the task). |
| **[K]** | Gate result (`npm run test` / `typecheck` / `build` / `lint`) executed green by the release lead; the record's author did not re-run the full suite. |
| **[S]** | Static count of `it(` / `test(` blocks via `grep` — not an executed test count. |

Where later work changed a behavior, the row carries a **0.3.0:** note. ### 6.2 Multi-Language Resolution Honesty Rule

Resolution labels are fixed per language by each worker's `PROTOCOL.md` and analyzer, and capability declarations never claim more than the analyzer does:

1. **Python:** `verified` = target defined in the same module (module-level `def` / `class`, `self.<m>` member table, `SameModuleClass.<m>`); `ROUTES_TO` is always `verified` (syntactic decorator → handler binding); `heuristic` = imported module symbol (edge carries `ambiguity`; no full type inference, so monkey-patching and runtime DI are out of reach); `unresolved` = local variable / builtin / unknown name → `UnknownExternal`, never an invented target.
2. **Go:** same-package bare-identifier top-level `func` → `verified` (local shadowing is indistinguishable from the AST alone — documented); `pkg.Func` calls, unique method names, interface-method candidates and imports outside the analyzed set → `heuristic` + ambiguity (no `go/types`); builtins → no edge; multi-candidate or unresolvable selectors → `unresolved` + candidate list; `symbolResolution:false` is shown on the MCP surface as `"heuristic-only (no semantic L2)"`.
3. **Rust (0.3.0):** same-module bare call → `verified`; qualified-path call matched on its last two segments → `heuristic` with `unverified-module-prefix-suffix-match` (module prefixes and `use` imports are not validated); a single method-call candidate (`x.foo()`) → `heuristic` (no trait dispatch); several candidates (bare, qualified-path or method calls) → `unresolved` + `UnknownExternal` with every candidate in `ambiguity` (no edge to any candidate); no candidate → `unresolved` + `UnknownExternal`. Before 0.3.0 a single qualified-path match was labelled `verified`.
4. **Shared:** route detection in Python / Go / Rust is syntactic (decorators, `HandleFunc` and chi/gin/echo registrations, attribute macros) and carries span + `sourceHash` + `analyzerId` evidence; missing or unbuildable workers degrade inside the adapter to L0/L1 with explicit warnings.

Two shorthand phrases in the original task brief did not match the code and were corrected at the time: Go package-qualified calls are `heuristic` + ambiguity, not `verified`; and Rust was not purely heuristic.
