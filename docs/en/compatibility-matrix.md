# Compatibility Matrix — Host × Outcome

> **Language:** [Türkçe](../compatibility-matrix.md) | **English** · [Documentation Hub](README.md)

> **Status:** reflects Causoryn 0.3.0 (default `core` tool profile with 11 tools). The live host CLI runs in the matrix below were recorded before 0.3.0, when `tools/list` returned the 29-tool catalog; the 0.3.0 tool profiles are covered by automated tests (see [Tool profiles in 0.3.0](#tool-profiles-in-030)), not by a re-run of the host CLIs.

> Evidence: host guides [Claude Code](hosts/claude-code.md), [Codex](hosts/codex.md), [ZCode](hosts/zcode.md), [Antigravity](hosts/antigravity.md) and `integrations/zcode/causoryn/README.md`. Rules applied: a smoke step that was not executed is reported as `NOT RUN` (never as passed), and smoke tests never leave permanent changes in a developer's real host configuration. `tests/release-docs.test.ts` guards this page: the Antigravity row must stay `NOT RUN`, and the ZCode row may only claim manifest and isolated CLI verification.

**Engine identity:** `causoryn@0.3.0`, MCP over stdio (`@modelcontextprotocol/sdk` 1.32.2, envelope `schemaVersion: "2.0"`). Historical runs were recorded against `causoryn@0.1.0` (2026-11-08/10) and the `0.2.x` packaged CLI (2026-11-19).

**Tool profiles:** `tools/list` publishes the default **11-tool `core` profile** unless another profile is selected with `--tool-profile <list>`, `CAUSORYN_TOOL_PROFILE` or `CAUSORYN_CONFIG.toolProfile` (in that order of precedence; default `core`). `wiki` adds 7 Living Wiki tools, `history` adds 2 architecture-history tools, profiles combine with commas (`--tool-profile wiki,history`), and `full` publishes all **32** tools (the 29 legacy names plus `causoryn_status`, `causoryn_trace`, `causoryn_contracts`), with deprecation notes on the superseded legacy tools. `causoryn setup` registers `<node> <runtime>/scripts/causoryn.mjs mcp --allow-cwd --auto-data-dir --client <id>` for every host, so every host starts with `core`; to use another profile, re-run `causoryn setup --tool-profile <list>`, add `--tool-profile …` to the registered arguments, or set `CAUSORYN_TOOL_PROFILE` in the host's server environment (re-running `setup` keeps such edits). See [MCP Tool Contracts](tool-contracts.md).

**Same engine everywhere:** the npm distribution package `packages/causoryn` (`npx causoryn setup`) and the monorepo bundle (`packages/mcp-server/dist/mcp-server.mjs` + `dist/index-worker.mjs` + vendored `node_modules/better-sqlite3/`) run the same engine. The bundle is deliberately multi-file because the native `.node` addon cannot be inlined into JavaScript. All hosts on one machine share one SQLite WAL database per workspace (`<base>/workspaces/<slug>-<hash12>/graph.sqlite`, base `--data-dir` > `~/.causoryn` for every host, ZCode included; `ZCODE_PLUGIN_DATA` only as a fallback when `~/.causoryn` is unusable); `--client` is only a diagnostic label, and the `build_leases` table keeps two hosts from publishing a snapshot at the same time.

**Verification environment:** live host runs on Windows x64 (build 10.0.26300), Node.js ≥ 24. The 3-OS GitHub Actions matrix (`.github/workflows/ci.yml`: `ubuntu-latest`, `windows-latest`, pinned `macos-15`) runs the build, package, security and test gates on all three operating systems.

## Honesty Notes

1. **Two of the three CLI hosts were verified by running the host CLI; the Antigravity `agy` CLI could not be run.** Host installation coverage is therefore reported as 2/3, with the remaining host explicitly `NOT RUN` and a ready-to-run checklist in the [Antigravity guide](hosts/antigravity.md).
2. **The ZCode row is limited to manifest validation and isolated CLI configuration.** ZCode marketplace installation is GUI-only, and smoke tests must not leave changes in a developer's real ZCode installation. Setup instructions ([ZCode guide](hosts/zcode.md), `integrations/zcode/causoryn/README.md`, `npx causoryn setup --client zcode --yes`) are documented; the interactive desktop install remains `NOT RUN`.
3. **stdout hygiene is checked in two layers.** All four hosts spawn the same engine, so process-level stdout discipline carries across hosts (unit suite, 5 independent spawn sessions in the security suite, the Claude Code and Codex manual runs, the `.tgz` E2E). Live host observation was done only on Claude Code and Codex.
4. **The live host runs predate 0.3.0.** They observed the 29-tool catalog. The 11-tool `core` default and the other profiles are verified by the automated tests listed above; repeating the Claude Code and Codex smoke with 0.3.0 is not recorded here.
5. **Platform boundary.** Live host CLI runs were on Windows x64. CI runs every build, package, lint, secret-scan and test gate on `ubuntu-latest`, `windows-latest` and `macos-15`; live interactive macOS / ARM64 host smoke remains `NOT RUN` and is an open `1.0.0` gate.
6. **Parity boundary.** Cross-host parity is defined by the MCP tool schemas and contract tests. Equivalent host UI or permission behavior is not claimed, and Causoryn cannot make a host model choose a tool.
