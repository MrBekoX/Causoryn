## `v0.2.2` Security Boundaries

**Bundle identity:** `packages/mcp-server/dist/mcp-server.mjs` SHA-256 `78cd773f190c9675a90972555434770f160fe268f3dd419a1d69bf036e192130`. `dist/bundle-manifest.json` records this hash and 35 entries including the native SQLite runtime. The hash identifies the local artifact. The F6 results below describe the dated test sessions in the matrix.

- `causoryn_export_documentation` writes to destinations authorized by `output.allowedOutputDirs` using a temporary file and rename. `--auto-data-dir` puts exports outside the source tree. A manually authorized export directory may be inside that tree. An undeclared directory returns `EXPORT_NOT_ALLOWED`. An unsafe file name or path escape returns `PATH_DENIED`. See `packages/graph/src/export.ts`, `packages/workspace/src/output-policy.ts`, and `packages/mcp-server/src/runtime-cli.ts`.
- Optional `annotations` are text supplied by the user or host model. The server enforces the schema and size budgets and validates `moduleId`, `nodeId`, `evidenceId`, and `keyFiles` against the snapshot and projection. Invalid references return `INVALID_ARGUMENT`. Review the prose for factual accuracy. See `packages/graph/src/architecture-annotations.ts`.
- The default `view="architecture"` HTML is script-free with a `default-src 'none'` CSP. Opt-in `view="interactive"` retains the offline boundary and permits a local embedded script. Display text is escaped, the data island is serialized safely, and the script uses no `innerHTML`, `fetch`, or CDN. See `packages/graph/src/architecture-export.ts`, `packages/graph/test/architecture-export.test.ts`, and `packages/mcp-server/test/architecture-export-tool.test.ts`.
- The MCP analysis and rendering code makes no model API calls. Host model usage and network policy are controlled by the host. npm installation and a cold Rust worker `cargo build --locked` can access package sources. The historical Node `net-guard.cjs` evidence covers the exercised process and fixture paths. [Language analyzers](language-analyzers.md)

## Historical F6 Scope and Methodology

The F6 tests targeted the **packaged bundle output** and its vendored native SQLite runtime.

- **Build command:** `node packages/mcp-server/scripts/build-bundle.mjs` (equivalent to `npm run build:bundle --workspace packages/mcp-server`); determinism is proven in the F1 suite (two builds produce bit-identical manifests) and `writeFileAtomic` eliminates partial-write (`ENOENT`) windows during parallel test runs.
- **Behavioral tests** spawn the bundle as a REAL child process (not `InMemoryTransport`): `tests/security-release/helpers/bundle-client.ts` — performs MCP `initialize` + `notifications/initialized` handshake over line-buffered NDJSON JSON-RPC, exposing all `stdout`/`stderr` lines to credential-leak scanning.
- **Protected clone discipline:** the file spawned by behavioral sessions and the file inspected by static scanners are a SINGLE protected clone snapshot (`cloneBundleTo`: copies `mcp-server.mjs` + `mcp-server.mjs.LEGAL.txt` + `node_modules` + `bundle-manifest.json` with a 5-attempt retry against concurrent rebuild races — `CLONE_MAX_ATTEMPTS = 5`). The `F6-K0` identity-binding test verifies that every manifest sha256 entry matches the clone byte-for-byte — any torn copy during a parallel rebuild fails RED immediately.
- **Static scans** inspect the entire bundle and all vendored files (including native binaries).
- **Detector honesty:** every static scanner includes a CANARY self-test — no scanner counts as green unless it catches a planted synthetic specimen first (red-capability proof). Behavioral tests use planted bait markers designed to fail red on regression.
- **2026-11-10 re-verification:** every row in this matrix was independently re-executed — bundle identity (`sha256` + manifest match), F6 suite (32 tests), full `tests/security-release/` suite (36 tests), complementary suites (100 + 57 tests), static grep scans (secrets/network/shell/URLs), and `tsc -p tsconfig.typecheck.json` — all green. Row 6 (malicious Git refs) was elevated from workspace-source unit tests to **bundle-level behavioral proof** (`F6-K7`), proving real `git cat-file` commit-SHA resolution and `INVALID_REVISION` rejections inside a live spawned bundle process.

Test triad: every row pairs POSITIVE (in-policy succeeds) and NEGATIVE (out-of-policy rejected with a fixed error code) executed test evidence; PARTIAL is either an executed boundary test or an explicitly labeled **(note)** methodology/documentation boundary.

## v0.2.0 (K-021 / K-022) Defense-in-Depth Hardening

On top of the F6 packaged-bundle matrix, the `K-021` multi-host distribution and `K-022` open-source release-readiness tracks added five defense-in-depth controls verified by automated tests:

1. **Sensitive user & OS system directory rejection on `--allow-cwd` & MCP `roots/list`:** `packages/mcp-server/src/runtime-cli.ts` (`:428-560`) strictly rejects `$HOME`, filesystem roots (`/`, `C:\`), data and plugin install directories (`~/.causoryn/runtime`, `_npx`, `node_modules`, `.claude-plugin`, `.zcode-plugin`, `.codex-plugin`), sensitive user directories (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, `~/.claude`, `~/.codex`, `~/.zcode`), and OS system directories (`/etc`, `/System`, `/usr`, `/proc`, `/sys`, `/root`, `C:\Windows`, `C:\Program Files`, `C:\ProgramData`) during zero-config CLI startup and dynamic desktop IDE `roots/list` binding. `--auto-data-dir` provisions `0o700` storage strictly outside authorized roots with CWE-59 dangling-symlink protection.
2. **`git-read.ts` minimal env allowlist & post-open `fstat`/TOCTOU verification:** `packages/graph/src/git-read.ts` (`:189-228, 518-602`) strips parent-process secrets via a 10-key `buildGitEnv` allowlist while forcing `GIT_CONFIG_NOSYSTEM=1` and `GIT_TERMINAL_PROMPT=0`; `working-tree` blob reads use `O_NOFOLLOW` on POSIX followed by post-open `handle.stat()` + `lstat`/`realpath` + `dev`/`ino` inode identity verification before bounded chunked reads.
3. **Pre-import Node `>=24` guard & `--expected-version` pin:** `packages/causoryn/scripts/lib/node-version-guard.mjs` exits cleanly with code `2` on `stderr` before loading native addons or Node 24 APIs (preserving strict `stdout` JSON-RPC hygiene); `packages/causoryn/scripts/plugin-mcp-launcher.mjs` enforces fail-closed `--expected-version` / `CAUSORYN_EXPECTED_VERSION` verification against `package.json`.
4. **Expanded 13-root `secret-scan` & deterministic Release Roslyn binary hygiene:** `scripts/secret-scan.mjs` scans **13 directory roots** (`packages`, `adapters`, `apps`, `native`, `scripts`, `integrations/zcode/causoryn`, `integrations/zcode/.claude-plugin`, `integrations/antigravity/causoryn`, `.github`, `.claude-plugin`, `.agents`, `docs`, `skills`) + **13 root text files** against credential, private-key, personal-email, and non-generic user-profile-path patterns (`0` matches). The Roslyn worker compiles with `-c Release -p:DebugType=none -p:ContinuousIntegrationBuild=true -p:SatelliteResourceLanguages=en` so zero local machine PDB paths leak into redistributed DLLs (`verify-package-ready.mjs`).
5. **SHA-pinned 3-OS CI, OIDC provenance, CycloneDX SBOM & 0 `npm audit` vulnerabilities:** `.github/workflows/ci.yml` (`ubuntu-latest`, `windows-latest`, `macos-latest`) and `.github/workflows/release.yml` pin every GitHub Action to a 40-character commit SHA, enforce `npm ci --ignore-scripts` and `cargo build --locked`, generate `SHA256SUMS.txt` + a 13-component CycloneDX 1.5 SBOM (`causoryn-sbom.cdx.json`) via `scripts/generate-sbom.mjs`, attest build provenance (`actions/attest-build-provenance`), and publish via tokenless npm OIDC (`npm publish --provenance --access public`); upgrading to `eslint@10.15.0` and `typescript-eslint@8.73.0` brings `npm audit` to **0 vulnerabilities**.

## Honesty Notes (ADR-010)

1. **Packaging fidelity (bare F1 bundle vs `packages/causoryn` K-021 distribution):** the bare F1 bundle directory (`packages/mcp-server/dist/`, 35-file manifest) does not carry TypeScript default library declarations (`lib.*.d.ts`); by contrast, the open-source distribution package `packages/causoryn` (`npm run build:package`, `K-021`) stages `dist/typescript-lib/lib*.d.ts` and `adapters/typescript` (`resolveTypeScriptLibDir`) discovers them automatically to reach full `state: "ready"` on sources referencing global types (`Promise`, `Record`, `Array`; verified in `tests/open-source-distribution.test.ts`). The bare F1 clone test (`F6-K3`) omits `typescript-lib/` and therefore uses a global-free fixture; all security invariants hold identically in both modes.
2. **"Single-file" claim:** the artifact is NOT a single file: `dist/mcp-server.mjs` + `dist/mcp-server.mjs.LEGAL.txt` + `dist/node_modules/better-sqlite3/` (33 files including `LICENSE`) — reported transparently per ADR-010 because native `.node` addons cannot be inlined into ESM JS.
3. **`child_process` surface:** legitimate, strictly bounded `node:child_process` usage spans 7 modules — (i) `packages/graph/src/git-read.ts` read-only git (`execFile`, subcommand allowlist `cat-file`/`ls-tree`, `REF_PATTERN` validation, minimal env allowlist), (ii) the shared sidecar IPC core `packages/sidecar-ipc/src/index.ts` and the 4 language sidecar `worker-process.ts` modules (`adapters/csharp-roslyn`, `adapters/python`, `adapters/go`, `adapters/rust` — literal command + fixed argv + env allowlist + `responseMaxChars`/`stderrMaxChars` budgets; numeric child-PID process-tree kill on Go `go run` timeouts), and (iii) the Rust toolchain helper `adapters/rust/src/cargo.ts` (`spawn`/`spawnSync` with literal `cargo` probe/build + numeric child-PID tree kill on timeout). Shell interpolation is zero everywhere (`shell: false`).
4. **URL literals:** URL strings inside the bundle text are documentation/spec identifiers (MCP spec, `aka.ms/tsconfig`, RFCs, `ajv` `data.json`, JSON Schema `$schema` URIs) — not outbound network clients; zero runtime network egress is behaviorally proven via `net-guard.cjs`.
5. **Scope boundary:** K6 netguard behavioral proof covers executed session paths (`initialize` → `tools/list` → index → export HTML → exit) and complements the full-bundle static transport scan (`F6-K2`).
6. **K7 fixture git dependency:** the POSITIVE branch's "commit SHA resolved" claim requires a real git repository (`working-tree` resolves without git in `services-wiki.ts`), so the distinguishing proof is running `git cat-file -t` against a real commit SHA inside the spawned bundle, paired with `INVALID_REVISION` rejections on malformed/unknown refs.
