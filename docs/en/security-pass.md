# Security Audit and Supply-Chain Boundaries

> **Language:** [Türkçe](../security-pass.md) | **English** · [Documentation Hub](README.md)

> **Status:** reflects Causoryn 0.3.1 (pre-1.0). The packaged-bundle threat matrix below was last re-run on 2026-11-24 (see [Methodology](#packaged-bundle-test-methodology)).

> **Threat model in one paragraph:** Causoryn analyzes repositories it does not trust. Source files, comments, configuration files, Git metadata, and toolchain configuration inside an analyzed workspace are treated as data, never as instructions or executable configuration. Causoryn makes no model or telemetry calls, writes nothing into the workspace, keeps its own database in a separate data directory, and returns results only over MCP `stdio`.

**Bundle identity:** `packages/mcp-server/dist/mcp-server.mjs` SHA-256 `86dba82b383613ee70bc1c8bae9748e56b6c831f345c334e0a20f959621c8b64`. `dist/bundle-manifest.json` records this digest together with `index-worker.mjs`, `mcp-server.mjs.LEGAL.txt`, and the vendored native SQLite runtime (36 entries). The digest identifies one local build; the dated results below describe the test sessions listed in the matrix.

## 1. Runtime Security Boundaries

- **Exports:** `causoryn_export_documentation` writes only to destinations authorized by `output.allowedOutputDirs` (or the auto-configured `<data-dir>/workspaces/<slug>-<hash12>/exports/` directory), using an exclusive `flag: "wx"` temp file with `EEXIST` handling and an atomic rename. `view="interactive"` defaults to `causoryn-architecture-interactive.html` so it never overwrites the zero-JS `causoryn-architecture.html`. An undeclared directory returns `EXPORT_NOT_ALLOWED`; an unsafe file name or path escape returns `PATH_DENIED` (`packages/graph/src/export.ts`, `packages/workspace/src/output-policy.ts`, `packages/mcp-server/src/runtime-cli.ts`).
- **Offline HTML and CSP:** the default `view="architecture"` HTML has no script and uses `default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'`. The opt-in `view="interactive"` HTML computes the SHA-256 of its single embedded script and emits `default-src 'none'; script-src 'sha256-<hash>'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'` — no `script-src 'unsafe-inline'`, no `innerHTML`, no `fetch`, no CDN. Display text is escaped and the JSON data island is serialized safely (`packages/graph/src/architecture-export.ts`).
- **Host-written annotations:** optional `annotations` are text supplied by the user or the host model. The server enforces the schema and size budgets and checks `moduleId`, `nodeId`, `evidenceId`, and `keyFiles` against the snapshot and projection, collecting up to 25 errors under `INVALID_ARGUMENT`. Review the prose for factual accuracy; Causoryn does not (`packages/graph/src/architecture-annotations.ts`).
- **No model or telemetry calls:** the analysis and rendering code makes no model API calls (see the [No-LLM decision record](adr/ADR-002-no-llm.md)). Host model usage and network policy are controlled by the host. `npm install` and a cold Rust worker `cargo build --locked` can reach package registries.
- **Read-only, bounded file access:** inventory reads open files read-only (`O_RDONLY | O_NOFOLLOW` on POSIX) and re-check identity after opening; `tsconfig.json`/`jsconfig.json` loading and `extends` resolution stay inside the root (`O_NOFOLLOW`, `fstat` `(dev, ino)` checks, depth and node budgets), and `configureConfinedCompilerHost` keeps the TypeScript compiler and module-resolution hosts inside the root and the bundled `typescript-lib`. Ignore discovery (`.gitignore`, `.git/info/exclude`, nested `.gitignore`) uses the same identity checks and bounded quotas. `ignore-matcher.ts` is a zero-RegExp, polynomial-time glob engine (no ReDoS).

## 2. Untrusted-Repository Toolchain & Sidecar Isolation

Repository-local configuration must never make the host execute code while Causoryn analyzes it. Tests: `tests/toolchain-isolation.test.ts`, `tests/toolchain-isolation-spawn.test.ts`, `tests/executable-resolution.test.ts`, `tests/git-read.test.ts`, `tests/git-read-hardening.test.ts`.

- **Absolute executables and trusted working directories** (`packages/sidecar-ipc/src/executable.ts`, with a self-contained copy in `packages/graph/src/executable-resolution.ts`): every tool the server starts (`git`, `dotnet`, `python`, `go`, `cargo`) is resolved to an absolute path by scanning `PATH` itself. Empty, relative, drive-relative, UNC and device `PATH` entries and entries inside the analyzed workspace are skipped; on Windows only `.com` / `.exe` candidates are accepted. Every spawn gets a working directory outside the workspace, and the child `PATH` is sanitized the same way. On Windows, process trees are stopped with `%SystemRoot%\System32\taskkill.exe`.

- **Shared IPC and doctor probes** (`packages/sidecar-ipc/src/index.ts`, `packages/causoryn/src/doctor.ts`): every sidecar spawn uses `shell: false` and `windowsHide: true`; an empty or NUL-containing `cwd` is rejected without spawning; the environment is rebuilt from a small allowlist (`buildAllowlistedWorkerEnv`) so parent secrets are not inherited. `causoryn doctor` runs its version probes with `cwd: os.tmpdir()`, `shell: false`, and an allowlisted environment.
- **Read-only Git** (`packages/graph/src/git-read.ts`): `execFile` with `shell: false`; subcommand allowlist `cat-file`, `ls-tree`, and `rev-parse` only in the form `rev-parse --verify --end-of-options <ref>^{commit}` (for `HEAD~N` / `HEAD^`); refs must match a linear-time pattern (`[A-Za-z0-9._/-]+` with optional `~N`/`^N` suffixes, max 200 characters) and pass further checks (no leading `-`, no `..`, no `@{`). The environment keeps 10 allowlisted variables and forces `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=<null device>`, `GIT_ATTR_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`, `GIT_NO_LAZY_FETCH=1`, `GIT_OPTIONAL_LOCKS=0`, `GIT_LFS_SKIP_SMUDGE=1`, and an empty `GIT_ALLOW_PROTOCOL` (no transport protocol allowed). Every invocation is prefixed with `-c` overrides (`core.fsmonitor=false`, `core.hooksPath=<null device>`, `core.pager=cat`, `core.sshCommand=false`, `core.askPass=`, `diff.external=false`, `protocol.allow=never`, per-protocol `protocol.<name>.allow=never` pins for `file`, `git`, `ssh`, `http`, `https`, `ext`, `ftp` and `ftps`, `safe.bareRepository=explicit`) so entries in a repository's `.git/config` cannot run external commands. Because the system and global config are nulled, the user's own system and global `safe.directory` entries are read once and forwarded as `-c safe.directory=<value>`, so repository-ownership checks keep working. Partial-clone (promisor) repositories are refused when the installed git is older than 2.45, the first release that honors `GIT_NO_LAZY_FETCH`. `working-tree` blob reads use `O_NOFOLLOW` on POSIX plus post-open `stat` + `lstat`/`realpath` + `dev`/`ino` identity checks before bounded chunked reads.
- **Go sidecar** (`adapters/go/src/{worker-process.ts,types.ts}`): forces `GOTOOLCHAIN=local`, `GOWORK=off`, `GOPROXY=off`; `GOENV` is not on the environment allowlist; `cwd` is the trusted `native/go-worker` directory.
- **Python sidecar** (`adapters/python/src/worker-process.ts`): launches `python -I -B -X utf8 <workerScriptPath>` (on POSIX `python3` is tried before `python`) with `cwd` = the worker directory and without `PYTHONPATH`. Per the [Python command-line documentation](https://docs.python.org/3/using/cmdline.html), `-I` (isolated mode) implies `-E`, `-P`, and `-s`: `PYTHON*` environment variables are ignored and neither the script directory nor user site-packages is added to `sys.path`, so a planted `sitecustomize.py` or shadowing module in the analyzed tree is not imported. `-B` disables `.pyc` writes; `-X utf8` enables UTF-8 mode for stdio on Windows.
- **C# Roslyn sidecar** (`adapters/csharp-roslyn/src/{worker-process.ts,types.ts}`): `cwd` = the worker DLL directory; forces `DOTNET_STARTUP_HOOKS=""`, `DOTNET_CLI_TELEMETRY_OPTOUT=1`, `DOTNET_NOLOGO=1`, `DOTNET_SKIP_FIRST_TIME_EXPERIENCE=1`. NuGet reference discovery reads `obj/project.assets.json` read-only, without following symlinks, with UNC guards and an 8 MB cap.
- **Rust / Cargo sidecar** (`adapters/rust/src/{cargo.ts,analyzer.ts,worker-process.ts}`): `cargo` is probed from its own directory, and `cargo build --locked` runs on a staged copy of the worker crate inside Causoryn's build cache (`CAUSORYN_RUST_TARGET_DIR`, default `~/.causoryn/cache/rust-worker-target`), with that copy as `cwd` and a fresh `--target-dir` inside it; a cache directory inside the analyzed workspace is refused, and an explicitly configured worker directory is never built in place. Builds run with `CARGO_BUILD_RUSTC_WRAPPER=""` and `CARGO_BUILD_RUSTC_WORKSPACE_WRAPPER=""`, and with `CARGO_HOME`/`RUSTUP_HOME` accepted only as absolute local paths. This keeps a `.cargo/config.toml` (`rustc-wrapper`) or `rust-toolchain.toml` in the analyzed repository or above the package directory from taking effect. A cached worker binary runs only if it matches its `<binary>.sha256.json` side file (`{ sourceFingerprint, binarySha256 }`), checked with `O_NOFOLLOW` + regular-file + SHA-256 verification.

Tested scenarios in `tests/toolchain-isolation.test.ts`: spawn options (`shell:false`, `windowsHide:true`, empty-`cwd` rejection); Cargo trusted `cwd`, wrapper clearing, and `CARGO_HOME`/`RUSTUP_HOME` sanitizing; a malicious `.cargo/config.toml` and `rust-toolchain.toml` in an untrusted directory never executing; tampered, missing, or mismatched `.sha256.json` and a symlinked cached binary being rejected; Python argv, trusted `cwd`, and a real worker ignoring a planted `sitecustomize.py`/`ast.py`; Go environment overrides; Roslyn `cwd` and `DOTNET_*` overrides. `tests/git-read.test.ts` runs real Git repositories with malicious `.git/config` entries (`core.sshCommand`, `core.fsmonitor`, partial-clone promisor fetch) and checks that none executes and no `.git/index.lock` is created.

## 3. Workspace Roots, Path Safety & Trusted Rules

- **Win32 UNC / device paths** (`packages/workspace/src/path-safety.ts`): `assertNotUncOrDevicePath` rejects `\\host\share`, `//host/share`, mixed-slash network forms, `\\?\…`, and `\\.\…` lexically, **before any filesystem call** (`realpathSync`, `statSync`, `lstatSync`), in `WorkspaceAccessPolicy`, `OutputAccessPolicy`, and `runtime-cli.ts`. This prevents a crafted path from triggering an outbound SMB/NTLM handshake (`tests/path-safety.test.ts`).
- **Root safety** (`inspectProjectRootSafety`, `packages/mcp-server/src/runtime-cli.ts`), applied to zero-config `--allow-cwd` binding and MCP `roots/list` roots: rejects filesystem roots; `$HOME` and every ancestor of it; Causoryn data directories (`~/.causoryn`, `ZCODE_PLUGIN_DATA`, `--data-dir`) and plugin, cache, and runtime install directories (including `_npx` and `node_modules` installs and Causoryn plugin manifests); sensitive user directories (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, `~/.claude`, `~/.codex`, `~/.zcode`); OS system directories (`/etc`, `/System`, `/usr`, `/proc`, `/sys`, `/root`, `/bin`, `/sbin`, `/lib`, `/dev`, and on Windows the `SystemRoot`/`ProgramFiles`/`ProgramData` locations); and the bare temp/system roots `/tmp`, `/var`, `/home`, `/Users`, and `os.tmpdir()` (subdirectories of these temp roots stay allowed).
- **Data directory:** `--auto-data-dir` creates the per-workspace directory with mode `0700`, strictly outside every authorized root, with symlink and ancestor checks (dangling-symlink protection).
- **Trusted architecture rules** (`packages/mcp-server/src/services-verification.ts`): `causoryn_verify_change` reads `.causoryn/architecture.rules.yaml` and `.causoryn/architecture.baseline.yaml` from the trusted Git base (`baseRef`, the manifest's recorded head, or `HEAD`), so a change cannot weaken the rules it is checked against. If it has to fall back to the working tree, the result carries `trustWarning: "architecture-rules-loaded-from-untrusted-working-tree"`.
- **Launcher guards:** `packages/causoryn/scripts/lib/node-version-guard.mjs` exits with code `2` on `stderr` before loading native addons when Node.js is older than 24 (keeping `stdout` clean); `plugin-mcp-launcher.mjs` enforces `--expected-version` / `CAUSORYN_EXPECTED_VERSION` against `package.json`.

## 4. Storage and Dependency Advisories

- **SQLite runtime:** `better-sqlite3` 13.2.0 bundles **SQLite 3.54.1**, which already contains the upstream fixes for CVE-2026-119373 and CVE-2026-119375.
- **No untrusted database files:** the real mitigation for database-file attacks is that Causoryn never opens a database or WAL file from an analyzed workspace. Its only database is its own `graph.sqlite` in the data directory, which must lie outside every authorized root (or an explicitly declared `storage.dataDbPath` that is validated the same way).
- **Configuration facts (not defenses):** new databases set `PRAGMA page_size = 4096` (SQLite's default page size) before the first table, and `symbol_fts` uses the FTS5 default `detail=full`. Code comments in `packages/storage-sqlite/src/{schema.ts,sqlite-repository.ts}` still describe these settings as CVE defenses; that description is inaccurate.
- **MCP SDK:** Causoryn uses `@modelcontextprotocol/sdk` **1.32.2** and runs only a `stdio` server (no HTTP transport). The TypeScript SDK advisory CVE-2026-104850 is fixed in 1.31.0, so 1.32.2 is not affected. (CVE-2026-115563 concerns the Python MCP SDK, which Causoryn does not use.)
- **SQL safety:** all external inputs are bound as prepared-statement parameters; FTS5 queries escape user terms into phrase expressions (`packages/wiki/src/search-query.ts`, `escapeFtsPhrase`).

## 5. CI/CD and Supply-Chain Hardening

1. **`.github/workflows/security.yml`:**
   - **`zizmor`** (`zizmorcore/zizmor-action`): static audit of all workflows (`strict-collection: true`, `persona: regular`, `min-severity: medium`, `advanced-security: false`, `annotations: true`, `fail-on-no-inputs: true`).
   - **PR dependency review** (`actions/dependency-review-action`): fails on `high`+ advisories and denies GPL/AGPL/LGPL licenses; shows OpenSSF Scorecard data and patched versions.
   - **Dependency audit:** `npm audit --audit-level=high` plus a fail-closed NuGet audit (`dotnet restore … --locked-mode`, then `dotnet list … package --vulnerable --include-transitive --format json`) that fails on any vulnerability of any severity, on any audit problem (including `NU1900`), when the live `api.nuget.org` source was not queried, or when zero projects were audited. Rust `Cargo.lock` is enforced by `cargo build --locked`, reviewed on PRs by dependency review, tracked by Dependabot, and audited by the `cargo-audit` job (`cargo install --locked --version 0.23.0 cargo-audit`, then `cargo audit --file native/rust-worker/Cargo.lock --deny warnings`, which also fails on unmaintained, unsound and yanked crates).
   - **Go vulnerability check:** the `govulncheck` job installs `golang.org/x/vuln/cmd/govulncheck@v1.10.0` on the toolchain selected by `native/go-worker/go.mod` (`GOTOOLCHAIN=local`, no toolchain download) and runs `govulncheck ./...` in `native/go-worker`; it fails on any reachable vulnerability in the worker or the Go standard library it is built with. `go.mod` declares the oldest still-supported Go release line (`go 1.26`; Go supports the two newest major releases), and `causoryn doctor` uses the same floor.
2. **`.github/workflows/codeql.yml`:** CodeQL for `javascript-typescript`, `python`, `csharp`, and `actions` (`build-mode: none`) and for `go` (`build-mode: manual`, building `native/go-worker`) with `security-extended` queries.
3. **`.github/workflows/scorecard.yml`:** OpenSSF Scorecard (`ossf/scorecard-action`, `publish_results: true`) with SARIF upload to code scanning; its `harden-runner` step keeps the container runtime enabled because the Scorecard action runs in Docker.
4. **`.github/workflows/release.yml` — three separated jobs:**
   - `verify-and-test` (`contents: read`): Linux `step-security/harden-runner` (`egress-policy: audit`, `disable-sudo-and-containers: true`), `fetch-depth: 0`, tag format + package version + `origin/main` ancestry checks, `setup-node` with `package-manager-cache: false`, `npm ci --ignore-scripts`, `npm audit --audit-level=high`, locked Roslyn (`-p:RestoreLockedMode=true`) and Rust (`--locked`) builds, typecheck, build, bundle, package build, lint, `npm run secret-scan`, `export-public-tree.mjs --verify-temp --ref HEAD`, and `npm test`.
   - `build-and-pack` (no tests): clean checkout, locked builds, bundle and package staging, `verify-package-ready.mjs` before `npm pack`, `SHA256SUMS.txt` + CycloneDX 1.5 SBOM generated immediately after packing, then the `digests` step exports the tarball name and the tarball and SBOM SHA-256 as job outputs (after checking that `SHA256SUMS.txt` lists exactly these two files) before an isolated tarball smoke test (`--version`, `doctor --json`, MCP `initialize`) runs packaged code; after the smoke test the artifacts and the exact file set are re-checked against those outputs. The SBOM lists the npm and NuGet components and the SQLite library compiled into the `better-sqlite3` prebuilds (version read from the vendored `sqlite3.h`).
   - `publish` (`environment: release`, `id-token: write`, `attestations: write`, `contents: write`): runs no build or test code; recomputes the downloaded tarball and SBOM digests and compares them with the `build-and-pack` job outputs, requires the exact artifact file set and a `SHA256SUMS.txt` listing exactly both expected files, then runs `sha256sum -c SHA256SUMS.txt`; attests provenance (`actions/attest-build-provenance`), publishes with tokenless npm OIDC Trusted Publishing (`npm publish "./$TGZ_FILE" --provenance --access public`, `--tag next` for prereleases; no `NPM_TOKEN`), and creates the GitHub Release (`--verify-tag`). Release assets are never overwritten: when the release already exists, a missing asset is uploaded and an existing one is downloaded and must have the same SHA-256, otherwise the job fails.
   - All three jobs run `harden-runner` with `egress-policy: audit`. A `block` allowlist for `publish` is derived from the job's observed network events rather than written by hand, because a missing endpoint would stop the job between `npm publish` and the GitHub Release.
5. **`.github/workflows/ci.yml`:** 3-OS merge gate (`ubuntu-latest`, `windows-latest`, `macos-26-intel`; the `main` ruleset requires `Verify (ubuntu-latest)`, `Verify (windows-latest)` and `Verify (macos-26-intel)`; the nightly and manually dispatched runs add arm64 `macos-26`), Linux `harden-runner`, locked NuGet restore via `packages.lock.json`, `cargo build --locked`, `npm audit --audit-level=high`, the 13-root `scripts/secret-scan.mjs`, and the public-export leak gate.
6. **`.github/dependabot.yml`:** npm (root workspace), Cargo (`/native/rust-worker`), NuGet (`/native/roslyn-worker`), and GitHub Actions, weekly and grouped, with a 7-day cooldown (`semver-major-days: 14` on package ecosystems). The Go and Python workers use only their standard libraries.
7. **Workflow regression tests (`tests/ci-workflow.test.ts`):** 40-character SHA pinning for every action, allowlisted actions, read-only top-level permissions, `persist-credentials: false`, no `${{ … }}` interpolation inside `run:` blocks, `harden-runner`, `zizmor`, `cargo-audit` and `govulncheck` jobs, CodeQL languages, Scorecard constraints, release job separation, release digest outputs, no `--clobber`, and Dependabot cooldown/grouping. The release digest scripts are also executed against fixture artifacts (where bash with GNU coreutils is available), covering a replaced tarball with a matching `SHA256SUMS.txt`, a missing checksum line, an extra file, a missing digest output, and a tag mismatch.
8. **Source hygiene:** `scripts/secret-scan.mjs` and the public export gate share one scanner (`scripts/lib/leak-scan.mjs`). It scans every tracked and untracked-not-ignored file (`git ls-files -z`; the 13 directory roots `packages`, `adapters`, `apps`, `native`, `scripts`, `integrations/zcode/causoryn`, `integrations/zcode/.claude-plugin`, `integrations/antigravity/causoryn`, `.github`, `.claude-plugin`, `.agents`, `docs`, `skills` and the 13 root text files are a required minimum), detects binaries by content, and fails closed on read errors. It looks for private keys, cloud/registry/API tokens, credentialed connection strings, assigned secret literals, personal emails, user-profile and local drive paths, and optional private terms from an untracked list (`.git/info/causoryn-private-terms` or `CAUSORYN_PRIVATE_TERMS`). The export gate reads the committed tree directly, so `.gitattributes export-ignore` cannot hide a file from it. The Roslyn worker is built with `-c Release -p:DebugType=none -p:ContinuousIntegrationBuild=true -p:SatelliteResourceLanguages=en`, and `verify-package-ready.mjs` rejects a DLL containing local paths or `.pdb` references.

## Packaged-Bundle Test Methodology

The matrix targets the **packaged bundle** and its vendored native SQLite runtime, not the TypeScript sources.

- **Build:** `node packages/mcp-server/scripts/build-bundle.mjs` (same as `npm run build:bundle --workspace packages/mcp-server`). Two builds produce identical manifests; atomic writes avoid partial-file windows during parallel test runs.
- **Real child process:** behavioral tests spawn the bundle as a real process (`tests/security-release/helpers/bundle-client.ts`), perform the MCP `initialize` + `notifications/initialized` handshake over line-delimited JSON-RPC, and expose every `stdout`/`stderr` line to the scanners. Sessions use the `full` tool profile (`CAUSORYN_TOOL_PROFILE=full`) so all 32 tools are reachable.
- **Protected clone:** the file that is spawned and the file that is scanned are one protected copy (`cloneBundleTo`: `mcp-server.mjs`, `mcp-server.mjs.LEGAL.txt`, `node_modules`, `bundle-manifest.json`; up to 5 attempts against concurrent rebuilds, `CLONE_MAX_ATTEMPTS = 5`). The identity-binding group (`K0`) checks every manifest SHA-256 against the clone byte for byte, so a torn copy fails immediately.
- **Detector honesty:** every static scanner first proves it can catch a planted synthetic specimen (canary). Behavioral tests plant bait markers that must stay absent.
- **Test triad:** each row pairs a POSITIVE case (in-policy input succeeds) with a NEGATIVE case (out-of-policy input is rejected with a fixed error code); PARTIAL marks either an executed boundary test or an explicitly labelled methodology note.
- **Latest run (2026-11-25, Windows, Node.js 24.16, git 2.53, bundle with the digest shown above):** `npx vitest run tests/security-release/ tests/toolchain-isolation.test.ts tests/git-read.test.ts tests/path-safety.test.ts` → **6 files, 58 tests passed** (security-release: 32 + 3 net-guard boundary + 1 client close = 36; toolchain isolation 9, git-read 5, path-safety 6). The complementary workspace, wiki, visualizer and stdout suites (`tests/visualizer-viewer.test.ts`, `packages/workspace/test/workspace-access-policy.test.ts`, `packages/wiki/test/wiki-search.test.ts`, `packages/wiki/test/wiki-export.test.ts`, `packages/mcp-server/test/stdio-stdout.test.ts`) were re-run on 2026-11-25: **5 files, 112 tests passed**. The static grep scans listed under [Reproducible Verification Commands](#reproducible-verification-commands) were last re-run on 2026-11-10.

## Honesty Notes

1. **Bare bundle vs distribution package:** the bare bundle directory (`packages/mcp-server/dist/`) carries no TypeScript default library declarations (`lib.*.d.ts`). The `causoryn` npm package (`npm run build:package`) stages `dist/typescript-lib/lib*.d.ts`, which `adapters/typescript` discovers automatically so sources using global types (`Promise`, `Record`, `Array`) reach `state: "ready"` (`tests/open-source-distribution.test.ts`). The bare-bundle clone used by the matrix therefore uses fixtures without global types; the security controls are the same in both modes.
2. **Not a single file:** the artifact is `dist/mcp-server.mjs` + `dist/index-worker.mjs` + `dist/mcp-server.mjs.LEGAL.txt` + `dist/node_modules/better-sqlite3/` (33 files including `LICENSE` and 8 prebuilt `.node` addons), because native addons cannot be inlined into an ESM file.
3. **`child_process` surface:** process spawning is limited to these modules: `packages/graph/src/git-read.ts` (read-only Git), the shared IPC core `packages/sidecar-ipc/src/index.ts` and the four sidecar `worker-process.ts` modules (`adapters/csharp-roslyn`, `adapters/python`, `adapters/go`, `adapters/rust`; absolute command resolved outside the workspace, fixed argv, environment allowlist, output budgets; numeric-PID `System32\taskkill.exe /T /F` for Go `go run` on Windows), `adapters/rust/src/cargo.ts` (absolute `cargo` probe/build from a staged crate copy; numeric-PID tree kill on timeout), and the CLI's `packages/causoryn/src/doctor.ts` version probes. No call site uses a shell (`shell: false` everywhere). Indexing additionally uses `node:worker_threads` (`packages/indexing/src/job-manager.ts`) to run analysis inside the same process.
4. **URL literals:** URL strings in the bundle are documentation or schema identifiers (MCP specification, `aka.ms/tsconfig`, RFCs, `ajv` data, JSON Schema `$schema` URIs), not network clients; the `net-guard.cjs` session shows zero outbound attempts.
5. **Scope of the network proof:** the behavioral session covers the executed paths (`initialize` → `tools/list` → index → HTML export → exit) and complements the full-bundle static transport scan. `net-guard.cjs` hooks in-process Node.js APIs only; child processes are constrained by the allowlists in section 2.
6. **Git fixture dependency:** proving "commit SHA resolved" needs a real Git repository (`working-tree` resolves without Git), so the positive case runs `git cat-file -t` against a real commit inside the spawned bundle and pairs it with `INVALID_REVISION` rejections.
7. **Git version:** `GIT_NO_LAZY_FETCH` is recognized by Git 2.45 and later (introduced together with `git --no-lazy-fetch`, see the Git 2.45.0 release notes). On older Git versions this variable has no effect, so partial-clone (promisor) repositories are refused there; for other repositories the remaining environment and `-c` overrides still apply. The hardening tests ran with Git 2.53.
8. **Executable lookup:** `git` and the toolchain commands (`dotnet`, `python`, `go`, `cargo`) are resolved by Causoryn to absolute paths from `PATH` entries outside the analyzed workspace, and `taskkill` is taken from `System32`, so a file inside the analyzed repository is never started in place of the real tool. A tool earlier on the user's own `PATH` (outside the workspace) is trusted, as for any program the user runs. `causoryn doctor` probes run with bare command names from `os.tmpdir()`.
9. **Caller-asserted test results:** `causoryn_verify_change` records test results supplied by the caller as `state: "host_asserted"` with `engineVerified: false`; Causoryn never runs the tests itself.
